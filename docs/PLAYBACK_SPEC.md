# PLAYBACK_SPEC

## 目的

この仕様は、再生の**内部実装経路**ではなく、ユーザーが体験する**挙動の一貫性**を定義する。

## 挙動仕様（ユーザー体験）

### 1. タイムスタンプクリック時の基本動作
- ユーザーがタイムスタンプを押したら、アプリはその `VOD / 時刻` へ移動して再生を開始する。
- ユーザー操作による再生では音声を自動でミュートに変更しない。
- クリックごとに「いま最終的に見たい再生位置」を更新し、常に最新要求を優先する。

### 2. 1クリック seek の成立条件
- 同じ VOD で、seek 可能なプレイヤーが準備済みなら、1クリックでその時刻へ移動する。
- このとき不要な再読み込み感を出さない。

### 3. 準備中クリックの扱い（last-click-wins）
- プレイヤー準備中に追加クリックが来た場合、最後に押された `VOD / 時刻` だけを採用する。
- 準備中にクリックされた全件を順に再生しない。

### 4. 準備完了直後の適用
- 準備が完了したら、最新要求へ**1回だけ**合わせる。
- 同一要求に対して複数回 seek を連打しない。

### 5. same/different VOD の体感
- same VOD と different VOD のどちらでも、クリック回数によって不自然な挙動差を感じにくくする。
- same VOD では、不要な再読み込み感を可能な限り抑える。

### 6. UI 追従
- `current start sec` と activity map は、常に「最後に選ばれた再生位置」に追従する。
- プレイヤー準備中も、UI は最新クリック先を指し続ける。

### 7. rewind
- rewind は、現在の実再生位置を基準に `-10秒` する。
- 実再生位置が取得できない場合のみ、直近の既知位置へフォールバックする。

## 実装メモ（仕様の主語ではない）

- デスクトップでは表示枠を元の場所に残し、Twitch プレイヤー本体だけを body 直下へ配置して Twitch の可視性判定を満たす。
- 通常の seek と VOD 切替は interactive player を使う。
- E2E テストではブラウザの自動再生制限を無効化せず、実利用に近い条件で検証する。
